## 이 문서들이 공유하는 전제 — 조용한 실패

이 인프라의 사고는 대부분 **에러가 아니라 이상한 성공**으로 나타난다.

```
그룹이 빈 채로 플레이북      →  0 hosts matched 로 성공 종료
kms_key_id 없이 apply       →  성공. 상태만 조용히 AES256 으로 되돌아간다
ACL 에 없는 태그로 조인      →  tailscale up 성공. 노드가 뜬 채로 고립
seal 블록이 반영 안 됨       →  지금은 되고 재부팅하면 멈춘다
Vault 노드에 kubeadm 설치    →  에러 없이 성공. 쓸모없는 패키지만 남는다
```

그래서 각 문서는 절차만 적지 않고 **"이걸 빠뜨리면 어떤 얼굴로 나타나는가"**
를 같이 적는다. "성공했는데 아무 일도 안 일어났다" 싶으면 그 문서의
증상 표를 먼저 본다.

배경은 워크스페이스의 `articles/20260731_vault-secret-centralization.md` 에 있다.

## 한 사실은 한 문서에만 적는다

같은 설명이 여러 곳에 있으면 고칠 때 한 곳만 고치게 되고, 나머지가 거짓말이
된다. 그래서 주제마다 주인을 정해 두고 나머지는 링크만 건다.

| 주제 | 주인 |
|---|---|
| 전체 토폴로지, 설계 근거 | 01 |
| 무엇을 어떤 순서로 세우나 | 02 |
| `cntlp-env.sh` 가 하는 일 | 03 |
| 시크릿 경로 설계·정책·읽는 법·회전 | 04 |
| Vault 백업·복구·인스턴스 재생성 | 05 |
| 상태 버킷·암호화 키 | 06 |
| Proxmox VM 재생성, tailnet 디바이스 잔존 | 07 |

문서를 고칠 때 이 표를 먼저 본다. **주인이 아닌 문서에 설명을 늘리지 않는다.**
